思路分析

注意到，当询问的 $k\ge2$ 的时候，只能够是原先的序列上下移动，所以答案恒为 $2$，$k=0$ 的时候答案显然恒为 $1$，所以我们只考虑 $k=1$ 的情况。

我们用 $dp_{i,0/1}$ 表示当前序列在 $i$ 位置对应到 $A_i\pm1$ 时分别的方案数。

不难注意到，如果 $A_{i+1}=A_i+1$，那么 $dp_{i+1,0}=dp_{i,0},dp_{i+1,1}=dp_{i,0}+dp_{i,1}$。反之也是类似的。

对于形式完全一样的的大量转移，我们不难往线段树和矩阵乘法处理动态 DP 那个方向去想，转移矩阵其实非常的好构造，用线段树维护一下就行，这样单次查询就是 $O(\log)$ 的了。

需要注意优化，无论是时间还是空间的。比如说你可以注意到对于长度为 $n$ 的上升/下降段，其转移矩阵总是一个对角线上都是 $1$，另一个对角线是 $0$ 和 $n$。

证明并不复杂，构造出长度为 $1$ 时的转移矩阵，发现满足要求，然后数学归纳法秒证，在此不在展开。

区间差分数组取相反数并不是特别好直接处理，但是我们注意到乘起来的每一个矩阵都是旋转 $180^\degree$ 形成的。

代数推导一下容易发现两个矩阵旋转过后乘起来的结果其实正是原矩阵的积旋转一下。多个矩阵同样可以数归证明。

注意仔细处理动态开点，不要增加不必要的节点，其实是可以在 $300MiB$ 左右创过去的。

具体来说，因为是区间修改，所以单次修改需要的空间大概就是 $2\log V$，查询精细实现可以做到不额外开点。

struct seg_treee{
	struct node{
		int ls,rs; val v; bool f;
		inline void flip(){ f^=1,v.flip(); }
	}re[200005*80]; int rc;
	inline val vat(int p,segv l,segv r){
		if(p) return re[p].v;
		tmp[0][0]=tmp[1][1]=1;
		tmp[0][1]=(r-l+1)%mod;
		tmp[1][0]=0; return tmp;
	}
	inline void pup(int p,segv l,segv r){
		segv mid=l+r>>1;
		re[p].v=vat(re[p].ls,l,mid)*vat(re[p].rs,mid+1,r);
		if(re[p].f) re[p].v.flip();
	}
	inline void newn(int& p,segv l,segv r){
		p=++rc; re[p].v=vat(0,l,r);
	}
	inline void flip(segv cl,segv cr,segv l,segv r,int &p){
		if(!p) newn(p,l,r); segv mid=l+r>>1;
		if(cl<=l&&cr>=r) return re[p].flip();
		if(cl<=mid) flip(cl,cr,l,mid,re[p].ls);
		if(cr>mid) flip(cl,cr,mid+1,r,re[p].rs);
		pup(p,l,r);
	}
	inline val que(segv ql,segv qr,segv l,segv r,int p){
		if(!p) return vat(0,max(ql,l),min(qr,r));
		if(ql<=l&&qr>=r) return re[p].v;
		segv mid=l+r>>1; val ret;
		if(qr<=mid) ret=que(ql,qr,l,mid,re[p].ls);
		else if(ql>mid) ret=que(ql,qr,mid+1,r,re[p].rs);
		else ret=que(ql,qr,l,mid,re[p].ls)*que(ql,qr,mid+1,r,re[p].rs);
		if(re[p].f) ret.flip(); return ret;
	}
