思路分析

算有道理的乱搞？

考虑对于某一堵墙，跨越 $v$ 份的面积为 $v^2k$，其中 $k$ 就是那个斜率常数。

于是不难看出来如果要分成 $k$ 份，那么每一份都是 $\frac{100}{k}$ 就是最优的，只不过我们不能取 $\frac{100}{k}$，我们只能取到几个相近的整数。

我们设计一个不依赖于上述性质的 $dp_{i,j,k}$，表示前 $i$ 份当中，北墙建了 $j$ 块草坪，南墙建了 $k$ 块草坪的最小总面积。

考虑转移：$dp_{i,j,k}=\min dp_{i',j-1,k'}+f_{i-i',k-k'}$，其中 $f_{n,m}$ 表示在南墙使用 $n$ 份建立 $m$ 个草坪的最小代价。

考虑转移：$f_{i,j}=\min f_{i',j-1}+k(i-i')^2$，显然 $f$ 可以直接 $O(n^3)$ 解出来。

但是 $dp$ 就比较悲催了，$3$ 维状态，$2$ 维转移，$n^5$ 还是浮点数计算，看起来比较困难。

于是我们发扬人类智慧，考虑一下我们前面提到的那个贪心：我希望每一块草坪尽量平均。

于是我在转移的时候，要求 $i-i'$ 必须在 $\frac{100}{n}$ 附近，而 $k-k'$ 也必须在 $\frac{m(i-i')}{100}$ 附近。具体来说，我们枚举标准值 $\pm3$ 的范围。然后过了。

参考代码如下：

CPP 
#include <bits/stdc++.h>
using namespace std;
#define int long long
constexpr int mod=998244353;
double k1,k2; int n,m,cnt,av1,av2;
double dp2[105][105],dp[105][105][105];
signed main(){
	ios::sync_with_stdio(0);
	cin>>k1>>k2>>n>>m;
	memset(dp,0x47,sizeof dp);
	memset(dp2,0x47,sizeof dp2);
	dp2[0][0]=dp[0][0][0]=0;
	for(int i=1;i<=100;++i)
		for(int j=1;j<=m;++j)
			for(int k=0;k!=i;++k)
				dp2[i][j]=min(dp2[i][j],dp2[k][j-1]+(i-k)*(i-k)*k2);
	av1=100/n; av2=100/m;
	for(int i=1;i<=100;++i)
		for(int j=1;j<=i&&j<=n;++j)
			for(int k=j;k<=i&&k<=m;++k)
				for(int oi=i-av1-3;oi<=i-av1+3;++oi)
					if(oi>=0&&oi<i)
						for(int ok=k-m*(i-oi)/100-3;ok<=k-m*(i-oi)/100+3;++ok)
							if(ok>=0&&ok<k)
								dp[i][j][k]=min(dp[i][j][k],dp[oi][j-1][ok]+dp2[i-oi][k-ok]+(i-oi)*(i-oi)*k1);
	printf("%.1lf\n",dp[100][n][m]);
}
