思路分析

VP 的时候分析中有一步整错了，但是阴差阳错的和正解一样，然后稀里糊涂的过了。写题解理思路的时候发现不对劲了。

我们考虑一个数被消灭掉的充要条件，下面将整个过程倒过来看，也就是把数字加回去，并且时间变成 $0-index$：

假设我在 $t_1

随后我们考虑在 $t2$ 时刻，这个数字最大能是多少。显然如果不到达理论上界，那么都是可以变成 $0$ 的。

在 $(t_1,t_2)$ 时间内，其上界稳定的乘 $2$，终于在 $t_2$ 时刻，其上界变成此前的 $2$ 倍多 $1$。

不难看出来，每一次多的这个 $1$ 会在之后乘上若干的 $2$ 的次幂，也就是说每一个数字的上界都是若干个 $2$ 的次幂的累加。

注意到直接利用这些性质是无法直接构造出来最优排列的，因此我们不妨二分一个答案，然后利用上面的性质进行判定。

那么，现在我已经知道我总共要做的操作的次数了。如果我在某一个时刻 $t$ 选择了某一个数字，那么其上界会增加 $2^{ans-t}$，或者等效成这个数字减少了 $2^{ans-t}$。

显然 $t$ 越靠前，减少的数字就越大，因此显然我们会将所有的数字从大到小进行操作。

如果一个数字一次性减到不超过 $0$ 了，那么这个数字就被解决了，否则我们把他重新放回去，让他在后面的轮中继续缩减即可。

于是我们用一个堆去维护这个过程即可，现在考虑外面的二分。

显然答案最小是 $n$，最大也不会超过 $n+\log_2 V$，因为我对任意一个数字执行 $\log_2V$ 次操作之后，所有的数字一定都不超过 $1$ 了，直接顺序操作一遍即可。

因此总的时间复杂度是 $n\log n\log\log V$，参考代码如下：

CPP 
#include<bits/stdc++.h>
using namespace std;
#define int long long
int t,n,a[200005],ans,l,r,mid; priority_queue<int>pq;
inline bool check(int v){
	while(pq.size()) pq.pop(); v--;
	for(int i=1;i<=n;++i) pq.emplace(a[i]);
	while(pq.size()&&v>=0){
		if(v>30) pq.pop();
		else if((1ll<<v)>=pq.top()) pq.pop();
		else pq.emplace(pq.top()-(1ll<<v)),pq.pop();
		v--;
	}
	return pq.empty();
}
signed main(){
	ios::sync_with_stdio(0);
	for(cin>>t;t;t--){
		cin>>n; l=n; r=n+31;
		for(int i=1;i<=n;++i) cin>>a[i];
		/*
		显然答案不会超过 n+O(\log)，不会低于 n
		对于一个数，他需要的操作次数只是他变成 1 的次数 +1
		如果对于一个数字，我还剩下充分多的操作次数，可以随便把他变成 1
		那么这个数字不会成为影响我最终结果的东西，不过他确实需要 1 次来变成 0

		越大的数字需要的次数越多，因此将数字从大到小先排一个序
		但是如果剩余次数不充分多会发生什么？
		之前拍出来的 hack： 9 3 2 研究一下，答案是 4：
		也就是说我认为我最大只能让 8 无影响的继续下去，可是我有一个 9
		构造中我不会对着 9 连续操作 3 次！
		但是这时候针对 9 的操作策略是不是说一旦变成奇数就操作一下？
		对于 9 看起来确实是这样，那对于 11 2 1 呢？并不是

		无论如何，我确实需要对着他操作一次，但是操作完一次之后呢？
		别的数字其实应该也被操作到了，但是我没太管他们

		事实上我们应该把这个数字给待定了：最小充分决策原则
		不过总之他现在确实需要操作，我们仍然扣除一次
		不过既然我们现在操作了一次，那么他的等效数值是什么？
		等效于扣除 2 的那么多次方，就是会多一，一路乘二乘下去
		然后后面累积还会有那么多操作
		*/
		while(l!=r)
			if(check(mid=l+r>>1)) r=mid;
			else l=mid+1;
		cout<<l<<endl;
	}
}
