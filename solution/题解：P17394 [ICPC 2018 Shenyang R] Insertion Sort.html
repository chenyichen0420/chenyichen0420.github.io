思路分析

神秘东西，不过有迹可循。

首先题意是简单的：询问有多少个 $[1,n]$ 的排列满足将前 $\min(n,m)$ 个数字排序之后是几乎有序的。注意数据点中确实存在 $m>n$ 的东西。

这里，几乎有序定义为最长上升子序列长度为 $n-1$，也就是说最多只有一个数字出现了乱序。

于是我们分情况讨论清楚就行了。注意前 $m$ 个位置会被排序，于是前 $m$ 个数字一定不会内部出现乱序。

我们考虑那个乱序的元素可能会在什么地方：

  1. 在前 $m$ 个当中，这意味着前 $m$ 个当中出现了一个过大的数值。
  2. 在后 $n-m$ 个当中。
  3. 其实不乱序何尝不是一种合法情况呢？

实际对应的选法就是三种：

  1. 前 $m$ 个当中出现了一个过大的数值。
  2. 前缀就是最小的 $m$ 个，但是后缀出现了一个乱序数值。
  3. 前缀空了一个小数值，但是后缀大部分元素严格递增，空出来的数值随便放一个位置。

先考虑第 $3$ 种情况。显然我前缀可以考虑将 $1\sim m$ 中的某一个位置空出来，然后自己占据 $1\sim m+1$ 中剩余的数字。此时后缀显然有 $n-m$ 个不同的空子可以给前面留出来的那个小值钻。因此这一部分的贡献是 $m(n-m)m!$。

再考虑第 $2$ 种情况。前缀其实已经锁死了，但是后缀的情况似乎不是特别好计数？总之我考场上懒得再去容斥了，于是写了一个暴力，直接枚举所有的长度为指定值的序列中乱序至多一个元素的方案数。贡献姑且记为 $m!f(n-m)$ 吧。

最后考虑第 $1$ 种情况。注意到后缀必须完全有序了，于是只需要考虑前缀这个过大的数字怎么选。注意这个数字只要选的是 $\ge m+2$ 的都是可行的，因为如果 $=m+1$，则会和我们之前说的漏一个 $=m$ 的较小值给后面的情况算重。于是这部分的贡献是 $(n-m-1)m!$。

将三部分的贡献直接加起来就是答案了。参考代码如下：

CPP 
#include<bits/stdc++.h>
using namespace std;
#define int long long
int t,n,m,p,ans,v,c[55];
vector<int>a; set<vector<int>>s;
signed main(){
	ios::sync_with_stdio(0); cin>>t;
	for(int i=1;i<=50;++i){
		s.clear();
		for(int j=0;j!=i;++j){
			a.clear();
			for(int k=0;k!=i;++k) a.emplace_back(k);
			for(int k=j;k!=0;k--){
				swap(a[k],a[k-1]);
				s.emplace(a);
			}
			a.clear();
			for(int k=0;k!=i;++k) a.emplace_back(k);
			for(int k=j;k!=i-1;k++){
				swap(a[k],a[k+1]);
				s.emplace(a);
			}
		}
		a.clear();
		for(int k=0;k!=i;++k) a.emplace_back(k);
		s.emplace(a);
		c[i]=s.size();
	}
	for(int tt=1;tt<=t;++tt){
		cin>>n>>m>>p; m=min(n-1,m); v=1;
		cout<<"Case #"<<tt<<": ";
		if(m==n-1){
			for(int i=1;i<=n;++i) v=v*i%p;
			cout<<v<<endl; continue;
		}
		ans=m*(n-m);
		for(int i=1;i<=m;++i) v=v*i%p;
		ans=ans*v%p;
		ans=(ans+v*c[n-m])%p;
		ans=(ans+(n-m-1)*v)%p;
		cout<<ans<<endl;
	}
}
