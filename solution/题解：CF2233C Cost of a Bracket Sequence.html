思路分析

我感觉我这个 $O(n)$ 的做法的思路是比较像人的。

首先，这个问题显然可以看作是套娃问题。内层的问题是给定括号串，问最长的合法子序列的长度，外层是怎么删能使得内层的答案最小。

非常套路的，我们想一下内层问题的解法。一个非常好想且显然正确的 $O(n)$ 的做法是这样的：

我们遇到左括号就直接选上，遇到右括号就能选就选。最后把多选的左括号删掉。

形式化的，我们认为左括号是 $+1$，右括号是 $-1$，我们维护答案和一个计数器。初值都是 $0$。

遇到 $+1$ 就将二者都 $+1$，遇到 $-1$ 时，如果计数器非 $0$，那么计数器 $-1$，答案 $+1$。

最终的答案是答案减去计数器，因为末尾可能有多要了的没匹配上的左括号。

现在考虑怎么去删点来让答案最小。

显然，一个上界估计是的我一次操作一定能够让答案减一，也就是每一对括号我们恰好删除其中一个，直到没有匹配的括号或者操作次数用尽。

考虑怎么达到这一点。

考虑最后出现剩余的一部分，显然对于这一部分删掉左括号不一定是最优的，因为左括号出现了剩余，因此这一部分我们一定只会删除右括号。

但是更靠前的部分呢？更靠前的部分是因为右括号过多被强制中断了，于是类似末尾的，删除右括号可能有别的右括号顶上来，于是我们只删除左括号即可。

显然时间复杂度可以做到 $O(n)$，参考代码如下：

CPP 
#include <bits/stdc++.h>
using namespace std;
#define int long long
int t, n, m; char c[5005], ans[5005];
struct sev {
	int l, r, c;
};
vector<sev>seg; int cp;
signed main() {
	ios::sync_with_stdio(0);
	for (cin >> t; t; t--) {
		cin >> n >> m >> c; seg.clear();
		for (int i = 0, j = 0; i != n; j = i = j + 1) {
			if (c[i] == ')') continue;
			int cnt = 1; j = i + 1;
			while (j != n) {
				if (c[j] == '(') cnt++;
				else cnt--;
				if (cnt < 0) break;
				j++;
			}
			if (j != n) cnt++; j--;
			seg.push_back({ i, j ,cnt });
		}
		for (int i = 0; i != n; ++i) ans[i] = '0';
		for (const auto& v : seg)
			if (v.c) {
				for (int i = v.l; i <= v.r; ++i)
					if (c[i] == ')' && m) m--, ans[i] = '1';
			}
			else {
				for (int i = v.l; i <= v.r; ++i)
					if (c[i] == '(' && m) m--, ans[i] = '1';
			}
		for (int i = 0; i != n; ++i) cout << ans[i]; cout << endl;
		/*
		删掉一些字符，使得最长闭合括号子序列的长度最小
		注意是子序列而非子串

		原问题可以使用贪心法 O(n) 的求解出来。
		具体来说，遇到一个左括号必加，遇到一个右括号如果能加就加
		于是最优决策是若干闭合串和末尾一个不必合串
		不闭合串我们挖掉末尾的 )，闭合串我们挖所有的 (
		*/
	}
}
