思路分析

思路自然的题目，有写题解却写的神神秘秘。

我们需要在被交互库干一车神秘的操作的前提下传递确定的信息，那肯定就是去找不变量啊！于是我们的核心就是找不变量。

考虑一个简单的问题：如果交互库不做任何操作的话，你能够设计出哪些方法传递信息？

显然你可以考虑让所有的黑点的 $x,y$ 的和，平均值，异或值什么的等于传递的目标点，然后把信息传递过去。

但是注意到你只能交换一次，所以说直接对 $x,y$ 进行位运算和乘除法基本就被排除了（可能构造不出来），剩下的就是做加法一类的。

做加法基本上就是直接加起来得到目标点，或者平均值等于目标点这两类，别的说实话想不到什么了。

选择加法显然是不行的：对于位移操作，记录信息中的目标点偏移了黑点数乘上偏移量，而实际上目标点只偏移了偏移量。

这再一次暗示了平均值的正确性，让我们来验证一下：

首先，在位移操作下其记录的信息确实是准确的。

其次，在旋转操作中，由于 $y\to x$，所以 $x$ 一维的信息是准确的，又由于 $n-x+1\to y$，$\frac{1}{c}\sum(n-x+1)=(n+1)-\frac{1}{c}\sum x=(n-x_0+1)$，所以 $y$ 一维的信息是准确的。

然后，在轴对称操作中，$x$ 一维的信息显然是准确的，$(n-y+1)\to y$，类似上面的推导，$y$ 一维的信息也是准确的。

最后是有点反直觉的取反操作。我们分析一下所有点的 $x$ 坐标总和 $\bmod n$，发现总和 $\frac{n(n+1)}{2}\times n$ 一定是 $n$ 的倍数，因此 $\frac{\sum x}{c}\equiv\frac{\frac{n(n+1)}{2}\times n-\sum x}{n^2-c}\pmod n$，如果有 $\gcd(c,n)=1$ 的话。事实上，题面中确实有。

至此，我们成功找到并检验了取平均值是一个一定可构造且不变的量，此题可解。参考代码如下：

CPP 
#include<bits/stdc++.h>
using namespace std;
#define int long long
int t,n,c,sx,sy,vx,vy,tx,ty; string type;
char mp[805][805];
inline void first(){
	for(cin>>t;t;t--){
		cin>>n; c=sx=sy=0;
		for(int i=0;i!=n;++i)
			for(int j=0;j!=n;++j)
				cin>>mp[i][j];
		for(int i=0;i!=n;++i)
			for(int j=0;j!=n;++j)
				if(mp[i][j]=='#')
					c++,sx+=i,sy+=j;
		cin>>vx>>vy;
		vx--,vy--;
		vx*=c,vy*=c;
		bool swp=0;
		for(int i=0;i!=n&&!swp;++i)
			for(int j=0;j!=n&&!swp;++j)
				if(mp[i][j]=='#'){
					sx-=i; sy-=j;
					tx=((vx-sx)%n+n)%n;
					ty=((vy-sy)%n+n)%n;
					if(mp[tx][ty]!='#')
						swp=1,cout<<i+1<<" "<<j+1<<" "<<tx+1<<" "<<ty+1<<endl;
					sx+=i; sy+=j;
				}
		if(!swp) cout<<"1 1 1 1\n";
	}
}
inline void second(){
	for(cin>>t;t;t--){
		cin>>n; c=sx=sy=0;
		for(int i=0;i!=n;++i)
			for(int j=0;j!=n;++j)
				cin>>mp[i][j];
		for(int i=0;i!=n;++i)
			for(int j=0;j!=n;++j)
				if(mp[i][j]=='#')
					c++,sx+=i,sy+=j;
		int rev=0;
		for(int i=1;i!=n;++i)
			if(c*i%n==1){
				rev=i; break;
			}
		sx=sx*rev%n;
		sy=sy*rev%n;
		cout<<sx+1<<" "<<sy+1<<endl;
	}
}
signed main(){
	ios::sync_with_stdio(0);
	if(cin>>type,type[0]=='f') first();
	else second();
}
